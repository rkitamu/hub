# hub-env — {{ENV_NAME}}

この環境の司令塔の作業場所。地図は `MAP.md`、ワークスペースの構成は `hub.toml` にある。

## 司令塔への頼み方

環境の `hub-env` ワークスペースにいる司令塔に、普段の言葉で頼む。ファイルを変更する依頼は作業として任せ、作業エージェントが作業ブランチへのコミット・push・PR 作成まで行う。マージはユーザーが行う。

| 頼み方 | 司令塔がすること |
|---|---|
| 「<子リポジトリ> の使い方を教えて」 | 地図と子のドキュメントを読んで答える |
| 「全体の状況を見せて」 | `hub-status` でエージェント、未コミットの変更、進行中の作業、期限の近い TODO をまとめる |
| 「地図とずれていないか見て」 | `hub-check` で `MAP.md`、`hub.toml`、実態を照らし合わせる |
| 「#30 を任せて」 | TODO を読み、作業名と依頼内容を確認してから、作業用のエージェントを立てて任せる |
| 「#30 の進み具合は？」 | 作業の `status.md` を読んで答える |
| 「止まった作業を再開して」 | `hub-work resume` でワークスペースとエージェントを立て直す |
| 「この作業を閉じて」 | 結果を報告し、OK をもらってから `hub-work finish` で閉じ、記録を archive へ移す。未コミットの変更があれば止めて相談する |
| 「<子リポジトリ> の xxx を直して」 | 作業として任せ、結果を確認する |
| 「hub の xxx を直して」 | 作業として任せ、結果を確認する |
| 「地図に xxx を足して」 | `MAP.md` や `hub.toml` の変更を作業として任せる |
| 「この指摘を今後のルールにして」 | 効く範囲に合わせて置き場所の案を示し、OK をもらってから反映する |
| 「頼み方の表を更新して」 | `commander.md` と地図に照らしてずれを調べ、案を示して OK をもらってから直す |
| 「全部立て直して」 | 確認してから `hub-reset` を実行する。作業のエージェントも閉じるので、あとで再開する |
| 「<ワークスペース> だけ立て直して」 | 確認してから `hub-reset <ワークスペース>` を実行する |
