# 頼み方の表を更新する

表は 2 か所にある。

- **hub の `README.md`:** どの環境でも読める汎用の表。環境固有の名前を書かず、`<子リポジトリ>` のように書く。
- **`<hub-env>/README.md`:** この環境の表。実際のエージェント名と、この環境だけの頼み方を書く。

hub の場所は `dirname "$(dirname "$(readlink -f "$(command -v hub-reset)")")"` で分かる。

## 手順

1. **現状を読む。** hub の `commander.md` と `README.md`、`<hub-env>` の `MAP.md`・`README.md`・`.claude/skills/*/SKILL.md` を読む。
2. **ずれを洗い出す。** 次を確かめる。
   - 司令塔に頼めることのうち、表に無いものはないか。
   - 表の行のうち、今はできないことや、古いコマンド・エージェント名を書いたものはないか。
   - 確認を挟む操作を、確認なしで進むように書いていないか。
   - 共通の行は、2 つの表で意味と順番が揃っているか。
   - hub の表に環境固有の名前が混ざっていないか。
3. **案を示す。** 変える行を表ごとに示し、ユーザーの OK をもらう。`<hub-env>/README.md` が無ければ、hub の表にこの環境の名前を入れた README の作成案を示す。ずれが無ければ、そう伝えて終える。
4. **反映する。** `<hub-env>/README.md` は司令塔が直す。hub の `README.md` は、hub の開発用エージェントに `herdr agent prompt` で頼み、結果の差分を確認する。
5. **報告する。** 変えた行を伝える。コミットはユーザーの許可を得てから行う。

## 表の書き方

- 列は「頼み方」と「司令塔がすること」の 2 つにする。
- 頼み方は「xxx をお願い」くらいの普段の言葉で書く。
- 司令塔がすることは 1 文か 2 文で書き、確認を挟む操作はそのことも書く。
